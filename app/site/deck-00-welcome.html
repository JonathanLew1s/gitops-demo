The basics · Git and GitHub

Git tracks every change. GitHub secures and automates the work around it.

Git

A version control system. It tracks every change, made by anyone, across a codebase of files: what changed, who changed it, when and why. Any earlier version can be compared or restored.

GitHub: secure

A cloud platform that extends Git. It controls who can change what, requires reviews and approvals, and keeps an audit trail.

GitHub: automate

It runs tasks on every change, such as checking code against your standards, scanning for secrets and personal data, building images and deploying.

In the VM worldThe change ticket, the spreadsheet, the approval email and the CAB minutes, recorded together and tied to exactly what changed.
SAY: definitions, not analogies. Git is version control. GitHub adds security and automation on top. We spend the morning on this.
The basics · Kubernetes and GitOps

Kubernetes runs applications from a description. GitOps keeps that description in Git.

Kubernetes

A platform that runs applications across a pool of servers. You declare the desired state, for example three copies of version 2. Kubernetes continuously makes the actual state match it.

What it does for you

It decides where each application runs, restarts failed copies, scales up and down, and rolls out updates a little at a time.

GitOps

An operating model where the desired state is stored in Git. Changes are made by pull request, reviewed, and applied automatically. Git is the source of truth.

In the VM worldYou build a server, install by hand, and hope test matches prod. Here you describe the result once, and the platform does it the same way every time.
SAY: three ideas. A pool of servers, you declare what you want, and the declaration lives in Git. The afternoon fills in the detail. BRIDGE: next, this is interactive, so we need everyone on GitHub.
