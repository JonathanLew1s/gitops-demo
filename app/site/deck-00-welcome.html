A day with Git, GitOps & Kubernetes

The aim of the day

To see how a modern team changes a live system: safely, visibly, and with nobody logging into a server.

See

A change proposed, checked by robots, approved by people, and applied by the platform.

Do

Make real changes yourselves. Four of you play roles in each exercise while everyone watches.

Judge

Decide what you would want to see before you trusted this way of working.

SAY: this is not a course in tools. Nobody needs Git on their laptop and nobody is expected to start using any of this tomorrow. The goal is to see what is possible and form your own view. MORNING: Git. AFTERNOON: Kubernetes. NEXT: two quick slides in plain terms, because the words are not obvious.
In plain terms · Git and GitHub

Git is a notebook that never forgets. GitHub is the office around it.

Git

Imagine a folder where every save is stamped: who changed what, when, and why. You can compare any two versions, and go back to any of them.

GitHub

The shared office where those folders live. People propose changes, others review them, robots check them, and the whole record is kept.

In the VM worldThink of the change ticket, the spreadsheet, the approval email and the CAB minutes: all in one place, and tied to exactly what changed.
SAY: do not worry about the words. A notebook with a stamped page for every edit, and an office where the notebooks are shared and checked. We will spend the morning on this.
In plain terms · Kubernetes and GitOps

Kubernetes runs your applications. GitOps means Git tells it how.

Kubernetes

A pool of computers you give instructions to: "keep three copies of this running". It makes that true, and keeps it true.

It looks after them

If a copy fails it starts another. If a computer dies the work moves. Like a manager who keeps the right number of staff on shift.

GitOps

Those instructions are files in Git. Change the file, and the platform follows. Nobody types commands on the servers.

In the VM worldYou build a server, install by hand, and hope test matches prod. Here you describe the result once, and the platform does it the same way every time.
SAY: you do not need the vocabulary yet. Three ideas: a pool of computers, you say what you want, and the instructions live in Git. The afternoon fills in the detail. BRIDGE: next, this is interactive, so we need everyone on GitHub.
