The basics · Git and GitHub

Git tracks every change. GitHub secures and automates the work around it.

Git

A version control system. It tracks every change, made by anyone, across a codebase of files: what changed, who changed it, when and why. Any earlier version can be compared or restored.

GitHub: secure

A cloud platform that extends Git. It controls who can change what, requires reviews and approvals, and keeps an audit trail.

GitHub: automate

It runs tasks on every change, such as checking code against your standards, scanning for secrets and personal data, building images and deploying.

In the VM worldThe change ticket, the spreadsheet, the approval email and the CAB minutes, recorded together and tied to exactly what changed.
SAY: definitions, not analogies. Git is version control. GitHub adds security and automation on top. We spend the morning on this.
The basics · Kubernetes and GitOps

Kubernetes: a hosting platform for container-based workloads

What it is

An open-source infrastructure platform for hosting containerised applications. Created by Google, now maintained by the open-source community.

What it does

You declare the desired state, for example three copies of version 2. It schedules, restarts, scales and updates workloads to keep the actual state matching it.

What comes with it

Built in: load balancing, secrets, scaling, self-healing. Standard add-ons: certificate management, observability and more.

Where it runs

Your own data centre, or managed on Azure, Google Cloud and AWS. The same platform everywhere.

GitOps is how we operate it: the desired state is stored in Git, changes are made by pull request, and Git is the source of truth.

In the VM worldYou build a server, install by hand, and hope test matches prod. Here you describe the result once, and the platform does it the same way every time.
SAY: what it is, what it does, what comes with it, where it runs. ACCURACY: load balancing (Services), secrets and scaling are part of Kubernetes itself. Certificate management (cert-manager) and observability (metrics, logs, traces) are standard add-ons that almost every cluster installs; ours runs cert-manager. Say "add-ons" if asked. HOSTING: this cluster runs on our own hardware. The same manifests run on Azure (AKS), Google Cloud (GKE) and AWS (EKS). BRIDGE: next, this is interactive, so we need everyone on GitHub.
